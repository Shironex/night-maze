# Sounds

Own work, no third-party material. The program reads the files at start
(`src/game/NightMazeApp.cpp`, through `audio::AudioEngine::load`) and plays them when the rules
in `src/game/SoundCues.cpp` say so. That file also holds the table that gives every sound cue
its file name.

All seven files are computed by `tools/make_sounds.py` from sine waves and noise. Nothing is
recorded and nothing is downloaded. The script uses only the standard library of Python (no
numpy, no other package). The files are 16 bit, 44 100 samples per second, mono except for the
crystal and the gate, which are stereo. Together they are about 0.7 MB.

| File | Cue | What it is made of | Peak | Source | Licence | Author |
|---|---|---|---|---|---|---|
| `flashlight_on.wav` | the flashlight is switched on | the contact of a switch, then 6 ms later the knock of the metal casing and its ring | -11 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `flashlight_off.wav` | the flashlight is switched off | the same switch, lower and duller, with a shorter ring | -12.5 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `flashlight_dead.wav` | the key on an empty battery, and the battery running out | the same switch muffled and without its ring, then one faint dry tick | -15 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `low_battery_pulse.wav` | the warning that repeats while the battery is low | two soft thumps below 120 Hz, like a heartbeat | -16 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `crystal_pickup.wav` | a crystal is collected | a struck glass: the inharmonic modes of a bar at 1397 Hz as detuned pairs, and a quieter second strike 1.6 times as high (stereo) | -3 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `lever_pull.wav` | a lever is pulled | a creak of wood and rope (a train of small slips through moving resonances), then a distant stone knock | -6 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |
| `gate_open.wav` | the gate opens (it sinks for 1.5 s) | stone dragging with a wandering loudness, a low rumble, and a settling thud at 1.36 s (stereo) | -3 dBFS | generated by `tools/make_sounds.py` | own work | Shironex |

The peaks differ on purpose: they are the mix of the game. The crystal and the gate stand in
front, the lever a step behind, the switch of the lamp is small, and the pulse is the quietest
because it repeats. No file peaks above -3 dBFS.

## Updating

Run `python tools/make_sounds.py` from the repository root. The script writes the same bytes
every time, so the files only change when the script does. To change a sound, edit its function
in the script (each one lists its layers in a comment) and run the script again.

## Checking

Nobody can hear a table of numbers, but the numbers can show that a sound is built as intended:

- `python tools/make_sounds.py --report` reads the files back and prints their length, peak,
  loudness, DC offset, first and last sample, where their energy sits and their strongest
  frequencies, then checks them against the intent of every sound (for example: the pulse lies
  below 120 Hz, the crystal lies above 1 kHz and is inharmonic, the dead click has far less ring
  than the working one). It ends with the number of checks that missed.
- `python tools/make_sounds.py --pictures some/folder` writes one PNG per file: the waveform
  above the spectrogram.

Whether a sound is pleasant, and whether the pulse is quiet enough to repeat for a minute, is
for a listener to decide, in the game, with headphones and with loudspeakers.

## Replacing a file by a recording

Keep the file name and the format (a WAV file: the build of miniaudio decodes nothing else)
and write its source, licence and author into the table above. In the script, take the sound
out of the list `SOUNDS`, so the next run does not write over the recording, and take its lines
out of `checks()`, which describe the generated sound and not the recording.
