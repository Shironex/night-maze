# The menu theme is a FLAC loop in a music group of its own
Status: accepted (2026-10-09)
Code: src/audio/AudioEngine.hpp, src/game/SoundCues.hpp, src/game/SoundCues.cpp, src/game/Settings.hpp, src/game/NightMazeApp.cpp, tools/make_music.py, cmake/Dependencies.cmake

Context: I chose a theme for the main menu, 72.7 s of stereo that loops. As a WAV file it is 12.8 MB, more than twice all 23 sounds together, and the engine decodes every file fully into memory.
Decision: the theme ships as assets/audio/menu_theme.flac (2.9 MB, 16 bit, 44 100 Hz, stereo), written by make_music.py itself, and miniaudio is built with its FLAC decoder. It plays in a third sound group, Music, with a music_volume setting that starts at 60 of 100. game::menuThemePlays names every screen: the theme plays on the main menu and its pages and nowhere else, fades in over 2.5 s and out over 1.5 s, and goes on from where it stopped. A screen added without a line there does not compile.
Why: FLAC is lossless, so the game plays the very samples I approved, and the decoder is plain C inside miniaudio with no new library. Halving the sample rate or going mono lost because both change the sound, and the two channels differ by design. Streaming the file lost because one decoded piece is 27.9 MB of memory at 48 kHz, which a streaming path with its own tests would not repay. The file peaks at -10 dBFS: at volume 60 its loudest moment is 5.6 dB under the click of a volume slider, the one sound a menu makes, and at 100 it is 3.3 dB above it.
Cost and revisit: 27.9 MB of memory for as long as the game runs, and about 0.2 s more at the start. I stream it if a second or longer piece arrives. Music plays in the menu only: a night has the wind and its own sounds. The theme stops while the window is not the active one, like the wind.
