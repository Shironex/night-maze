# The application has a folder of its own, and its state is held in one struct per system
Status: accepted (2026-11-05). Moves NightMazeApp out of src/game, where [game-domain-folders](game-domain-folders.md) had left it.
Code: src/app/CMakeLists.txt, src/app/NightMazeApp.hpp, src/app/ScenePasses.hpp, src/app/MenuNames.hpp, tests/LayeringTests.cpp

Context: NightMazeApp, its shared header and main.cpp joined every domain folder but sat beside them in src/game and src/, and the header of the class had grown to 1526 lines with about 150 members side by side.
Decision: main.cpp, NightMazeApp and its source files moved to src/app, which may include every folder and which no folder includes (a test in tests/LayeringTests.cpp). The members are grouped into one struct per system (AppShaders, SceneRenderers, RenderSettings, FrameState, MenuState, StoryState, SoundState, RoundClocks, SessionState), held as members in the old order of construction, and the shadow and scene passes became ScenePasses, which holds references to the members it reads under their old names. The shared header became MenuNames.hpp. Nothing the game does changed.
Why: The header now reads as the coordinator, and a system's state can be read in one short file. I rejected moving the screens, the menus and the campaign into classes of their own, because nearly every function there calls back into handleGameEvent and the other screens, so they would need a pointer back to the application and would hide the flow rather than split it.
Cost and revisit: The header is still about 900 lines, most of it the documented declarations of the coordinating functions, and the code reads one name longer (m_sound.audio). ScenePasses has to stay declared after the members it refers to. I reopen it if a screen grows a large body of its own that does not call back into the others.
