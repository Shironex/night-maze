# A frame is measured as three CPU times, four counters and one timer query a pass
Status: accepted (2026-10-12)
Code: src/core/Application.cpp, src/core/PeriodicAverage.hpp, src/gfx/RenderStats.hpp, src/gfx/TimerQuery.hpp, src/game/GpuPasses.hpp, src/game/NightMazeAppRender.cpp, src/game/NightMazeAppPasses.cpp, src/debug/categories/DiagnosticsCategory.cpp

Context: The only numbers were FPS and frame time, and with vsync both say "60" whatever a frame costs. A performance pass needs numbers that tell the CPU from the GPU and one pass from another.
Decision: The main loop times update, render and swap. The counters of draw calls, triangles, uniform lookups and texture binds are one object for the whole program in `gfx`, reset at the start of `onRender`. Eight passes each own a `GL_TIME_ELAPSED` query. Its answer is read in a later frame and only when `GL_QUERY_RESULT_AVAILABLE` says it is there, and a query that still waits is not started again. Times are averaged over the half second of the FPS display. A pass without a draw call is shown as not run.
Why: Handing a counter object to every renderer was rejected: it changes every draw function for a number that is only shown, and the game draws from one thread. Reading a query in the frame it ended was rejected too, because the program then waits for the card and the wait lands in the frame that is measured. Timer queries cannot lie inside each other in OpenGL 4.1, so the grass is a range between two parts of the scene pass.
Cost and revisit: How finely two ranges are told apart is up to the card. On an Apple M3 (measured 2026-10-12) Scene and Grass report the same number, the time of both together, because the card works on a framebuffer as a whole. The passes with a framebuffer of their own were told apart, and the bloom time matched the frame time won by switching the bloom off. Since the moon map starts with a copy of its still layer (see `moon-shadow-still-layer`), the moon pass reports about 0 ms there. So the debug window shows no sum of the passes. With vsync off the swap time does not go to zero: it is then the wait for the card. The CPU render time holds the menu and the debug window, and the counters and GPU times do not. Triangles made by the geometry shader of the grass are not counted. I reopen this if a pass needs to be split further or drawing moves to a second thread.
