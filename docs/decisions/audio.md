# Sound plays through miniaudio and every file is computed by a script
Status: accepted (2026-10-09)
Code: cmake/Dependencies.cmake, external/miniaudio/miniaudio.c, src/audio/AudioEngine.cpp, tools/make_sounds.py, tools/make_music.py, assets/audio/README.md

Context: the game was silent and I wanted it to be a portfolio piece. I needed a sound library, and sounds and music whose licence nobody can question.
Decision: I chose miniaudio 0.11.25, fetched at a pinned tag. All 23 WAV files in assets/audio come from tools/make_sounds.py, which uses only the Python standard library. The sounds that happen in the maze share one computed reverb, a stone room of 1.2 s, each with its own amount. The menu theme comes from tools/make_music.py: I wrote the notes into the script, and it computes the piano, the strings and the music box with numpy, in the same room made larger. It plays in a music group of its own (see menu-music).
Why: a script leaves no one else with rights to the files, the source is readable in history, and anyone can build the same bytes from the repository. Downloaded packs lost because every file would need its licence and author checked and listed. For the music I listened to the same notes played from recorded instruments and chose the computed render: recordings would bring a licence and files that are not in the repository. A music service lost for the same reason, and because the piece would not be my own work.
Cost and revisit: computed sound does not sound like a recording, and the piano is the weakest part of that. I replace single files with recordings if it falls short, following assets/audio/README.md. make_music.py needs numpy, the one package any tool here needs. Earlier: the first version had seven sounds, and until 2026-10-09 there was no room and no music.
